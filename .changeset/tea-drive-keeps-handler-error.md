`driveToDone` now rejects with the Cmd handler failure that left the run stalled, the same object, in place of `DriveStalledError`, and `onError` does not also hear it. Before, a handler failure that has no caller to reject at, a throw on a later hop or any throw or contract breach of a `Cmd.define`d handler, went to `onError` and the drive found nothing left to run, so the cause was lost. While `dispatch(start)` runs, the drive now holds such a failure and decides it at its one stall check, when that dispatch quiesces. A stall rejects with the first held failure, and every other one goes to `onError`, in order. A drive that resolves, or keeps waiting on a live Sub or Cmd, sends every held failure to `onError` at once. After that check nothing is held, so each failure is heard once, under its own phase, as soon as its outcome is known. The cost of holding is that a held failure is heard when `dispatch(start)` quiesces, not when it happens: a long start chain delays it (a throw on the second hop is heard after 303 ms instead of 2 ms when another hop runs for 300 ms), and a start chain that never quiesces keeps it held until the drive ends some other way, such as the quiescence cap or an abort. A store's refused save is not a handler's failure: it still goes to `onError` and the drive still stalls. A run you dispatch to yourself, with `run` and `dispatch`, is unchanged, and no export or signature changes.

**Breaking:** a caller that tells a stall apart with `catch (e) { if (e instanceof DriveStalledError) log(e.state) }` no longer gets a `DriveStalledError` when a Cmd handler's failure caused the stall: it gets that failure as the handler threw it. Handle the failure in the same `catch`. `DriveStalledError` still names every other stall, such as one a store's refused save left.

**Breaking:** a run with no `onError` whose settling State's Cmd throws on the first hop used to resolve without a sound, because the drive had already settled when `dispatch(start)` rejected. It still resolves, and the throw now goes to the sink, which with no `onError` is the default sink: it rethrows on a macrotask and ends a Node process. Pass an `onError` to keep the process alive.
