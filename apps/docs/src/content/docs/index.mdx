## The whole idea, in three lines

- A reducer is a **function**.
- A side effect is **data**.
- A bug is a **replayable trace**.

Every stateful thing — a Durable Object, a workflow, a React page, a queue consumer, a
cron, a widget, an extension — is the same loop wearing a different jacket. `@demlik/tea`
is that loop, written once: a pure reducer over discriminated unions, a typed effect
channel (`Cmd`), and a state-driven subscription topology (`Sub`). The runtime performs
the effects and sends the results back as messages. That separation is the whole game.

Because the reducer is pure and the effects are values, the same machine **replays**:
`replay()` re-decides every step identically from a recorded schedule, so tests need no
mocks and a production trace is a reproduction.

## Every host, one machine

The substrate is host-agnostic. The host adapters are subpath imports you add only for
the surface you use.

## Batteries, not bespoke try-catch

Resilience and flow are **wrappers over the same machine**, not features bolted into your
domain logic: retry with backoff, circuit breaker, rate limit, deadline, cache,
idempotency, debounce, throttle, saga compensation, pagination, polling and token refresh.
Each is a published subpath with its own semver promise.

## Why it is shaped this way

Every meaningful decision is written down and linked from the
[Explanation quadrant](/explanation/) — resilience built in-house rather than installed,
a Durable Object host layer rather than a DO framework, errors as data with a throw
reserved for a contract breach.
